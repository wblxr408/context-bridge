# 自动触发与设计依据

## 能力边界

自动发现技能只意味着模型可根据元数据选择它，不保证每轮必运行。启用后按阶段边界检查；技能本身不注册后台服务，不掌握未暴露的 token 指标。确定性监控需要宿主真实提供的上下文指标和生命周期接口，不能编造 hook 名称或配置。

若用户要求长期默认启用，可在 Codex 的 AGENTS.md 或 Claude Code 的 CLAUDE.md 添加以下轻量入口；只有写入该规则得到当前请求授权时才修改既有配置，不复制整套技能进去：

> 长任务在阶段结束、约束遗漏、预计大量读取或上下文压缩前，使用 context-bridge 评估是否需要检查点或新对话；无新信号时沿用判断。只加载对应分支的参考文件。先完成可校验的迁移包；新建对话仍须符合用户明确指令和工具权限。

不把“请写一个 skill”解释为安装后台自动化、修改所有项目指令或立即迁移当前任务。用户在 Codex 可调用 `$context-bridge`，在 Claude Code 可调用 `/context-bridge`；也可在任务开始时要求本任务按该规则运行。只在实际适配需要时读取 hosts.md。

## ContextRail 的借鉴范围

截至 2026-09-27 核对的两个同名项目：

- [contextrail.app 的 Contexts 文档](https://contextrail.app/docs/contexts)：采用有标识、摘要和依赖的结构化上下文单元。本技能借鉴其知识卡片组织方式，用 INDEX 定位并按需加载；不要求接入其服务。
- [IgorTitov/Contextrail](https://github.com/IgorTitov/Contextrail/blob/main/README.md)：采用有边界的代码模块、sidecar 元数据和限定任务范围的上下文简报。本技能只借鉴范围裁剪与入口索引，不移植其整个架构及并行交付体系。

这些设计有助于减少无关读取，但它们不构成聊天迁移无损或固定提速的证明。版本化包、冻结写入、SHA-256 与接收验证是本技能为迁移设计的机制，不能归因成上述项目已验证的能力。

[OpenAI Skills 文档](https://developers.openai.com/plugins/concepts/skills) 描述先用元数据发现技能，匹配后加载完整指令。本技能据此把判断、制包、恢复和集成分支分开，常规评估只加载入口和 decision。

## 如何校准

不固定按轮数切换。真实任务可记录迁移原因、接收端启动读取量、恢复耗时、遗漏修正次数、重复读取次数与是否完成下一工作块；优先减少遗漏，再调阈值/工作块大小。对比相似任务且注明模型、网络、缓存及任务复杂度差异，不能用单次耗时证明因果。
