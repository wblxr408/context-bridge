## 回答发布规则及实际修正

- `source_policy=remote_only` 在发送前删除本地来源和观察。无远程来源就确定性返回
  证据不足，零模型调用；同文的本地笔记不能替代远程出处。
- 已完成任务可沿用其原 scope 的不可变来源重新提问，不追加对话、不重新采集。
  本轮重用的是之前真实 MCP 保存的虚构原文，没有重新开放隧道。
- 候选先经完整 schema 和精确原句校验，再经单独的语义审查调用。失败最多修订一次；
  两次均拒绝则保留候选及费用但不发布答案。中断继续使用已保存步骤。
- `run_facts` 用 Decimal 从初始综合前的已完成调用计算，并在修订中保持同一快照。
  UI 明确它不含本次综合、审查和后续分析；总费用以账本为准。
- Nebius 严格 schema 解码曾持续输出空白并耗尽输出额度（任务
  `92c230440c7d4aab916ebe46530eacd4`，USD 0.000502）。综合角色改用 JSON object
  传输格式，仍由本地完整 JSON Schema 拒绝无效结构。
- 35B 审查曾误放行“当前费用未知”，也曾误拒绝正确的无关问题弃答，因此综合与审查
  升为实际可用的 Qwen3.5-397B。两次调用使用同一权重，不能宣称独立模型共识。
- 397B 仍曾误放行以退款引文装饰“咖啡偏好未记载”的答案，历史任务
  `faf1c95150b64b6db1b736cba807377f` 保留。补充引文相关性要求后，审查拒绝该保存候选。
  同一原问题的新任务先因不足证据却带引文被本地拒绝，修订成空引文弃答后才发布。
  UI 对不足证据状态直接显示“当前选定来源不足以支持回答”，不把生成的否定句当结论。
